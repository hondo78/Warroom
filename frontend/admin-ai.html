🤖 KI-Agent (Alert-Analyse)

Der Agent zieht periodisch neue Alarme heran, ruft ein LLM (OpenAI-kompatibel — LMStudio, Ollama, vLLM, OpenAI) und schlägt eine Aktion vor. Empfehlungen landen als pending in der Dashboard-Liste, bis sie ein Mensch freigibt — sofern Auto-Execute aus ist.

0 = deterministisch/konsistent, höher = kreativer. Für Security-Entscheidungen niedrig halten (0–0.3).
Obergrenze der Antwortlänge. Reasoning-Modelle brauchen Reserve für ihren internen „Think"-Block — großzügig lassen (≈3000).
Sprache der LLM-Default-Prompts, der Analyst-Chat-Antworten und der Telegram-Meldungen. Eigene (überschriebene) Prompts bleiben unberührt.
Wenn aktiv, führt der Agent nur nicht-destruktive Aktionen (acknowledge) ohne Freigabe aus. Block-Aktionen und Isolate bleiben immer manuell. Die Aktion ergibt sich allein aus den Schwellenwerten pro Quelle — es gibt keine Konfidenz-Berechnung mehr.
Wertet den Sophos-Central-Event-Stream (getrennt von Alerts) aus — Endpoint-Threat/C2/Exploit-Events. Pro neuem Event der konfigurierten Typen entscheidet das LLM block_ip / isolate / acknowledge.
Nur Events dieser event_type-Werte gehen ans LLM. Firewall-ATP-Events bewusst ausgenommen (über WAF/IPS abgedeckt).
Wenn aktiv, prüft eine separate Schleife jede neue WAF-Zeile mit 4xx/5xx-Status pro Source-IP. Regel: ≥ Schwelle Fail-Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip. Decisions landen im Audit-Trail; whitelistete IPs werden ohnehin verworfen.
Anzahl an 4xx/5xx-Hits derselben IP in 24 h, ab der geblockt wird (Default 4).
Prüft jeden neuen IDP/IPS-Event pro Source-IP. Regel: Schwere = high/critical ⇒ sofort block_ip; sonst ≥ Schwelle Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip.
Erkennt Brute-Force-Versuche. Regel: ≥ Schwelle Failed-Logins in 24 h pro IP ODER schlechte OSINT-Reputation ⇒ block_ip.
Wenn ein /24-Netz in Summe ≥ N Failed-Login-Versuche in 24 h sendet UND die Versuche von ≥ M unterschiedlichen IPs kommen, werden alle aktiven IPs dieses Subnetzes geblockt. Verteidigung gegen koordinierte Botnets.
Welche Login-Versuche der Agent sieht (Default 60 Minuten).
Richtwerte, ab wann ein Netz als koordiniert gilt — werden dem Agenten als Hinweis übergeben; er darf bei klarem Muster begründet abweichen.

🤖 KI-Agent — System-Prompts

Die System-Prompts pro Stufe (Alerts, WAF, IPS, Failed-Login, Verteilter Brute-Force, Triage) werden jetzt im Kontext der jeweiligen Workflow-Stufe bearbeitet — zusammen mit Trigger, Schwellen, erlaubten Aktionen und Auto-Execute.

Zur Agent-Workflow-Seite

KI-Analyst — Persona (System-Prompt)

System-Prompt für den freien Chat mit dem LLM (über KI-Chat, Teams und Telegram). Nicht erkannte Befehle werden als Gespräch mit dieser Analysten-Persona beantwortet. Leer = mitgelieferter Standard-Prompt. Benötigt einen aktivierten Agenten (LLM-Endpoint).

🔌 MCP-Server — Log-Suche fürs LLM

Stellt eine read-only Suche über die Firewall-Syslogs als MCP-Server bereit (Streamable HTTP unter /mcp), damit ein MCP-Client (Claude Desktop/Code …) die Logs per LLM durchsuchen kann. Tools: search_logs, count_logs, aggregate_logs, describe_logs.

Erforderlich, wenn aktiv. Im MCP-Client als Authorization: Bearer <Token> hinterlegen. Unabhängig vom Warroom-API-Key rotierbar.
