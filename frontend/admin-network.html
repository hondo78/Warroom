Interne Hostnamen

Löst Hostnamen für interne (private) IPs auf und zeigt sie überall an, wo eine interne IP erscheint. Quellen in dieser Reihenfolge: Sophos-Endpoints → Reverse-DNS (PTR) → NetBIOS. Für PTR privater Bereiche trage die IP deines internen DNS-Servers ein (der Standard-Resolver des Containers kann das i.d.R. nicht).

Kommagetrennt. Leer ⇒ System-Resolver. PTR-Records müssen existieren.
Firewall DHCP (SFOS XML-API)

Liest DHCP-Zuordnungen (IP → Client-Name) von der Sophos-Firewall und ergänzt sie als Hostname-Quelle „dhcp". Der API-Benutzer muss in der Firewall API-berechtigt und dessen Zugriff für Warrooms IP freigegeben sein.

Aus: Firewall-Infos kommen aus der XML-API. An: legt zusätzlich pro Central-Firewall einen Karten-Pin an (kann Dubletten erzeugen).
XML-API-Entity (kommagetrennt möglich). Firmware-abhängig; Standard liefert reservierte Zuordnungen.

                        


                        

                            
                        


                        

                        
nmap-Portscan interner Hosts

                        
Aktive Portscans einzelner interner Hosts (nur private IPs). Ergebnisse werden langfristig gespeichert; Port-Änderungen (Dienst neu/weg) werden nachvollzogen und optional alarmiert. Aktiv/intrusiv — standardmäßig aus.

                        

                            

                            

                            

                            

                            

                            

                            

                            

                            

                            

                        


                        

                        
Online-Status (Ping-Sweep)

                        
Regelmäßiger nmap-Ping-Sweep der bekannten internen Hosts, um den aktuellen Online-Status in der Host-Liste anzuzeigen. Leichtgewichtig (keine Portscans).

                        

                            

                            

                            

                            

                            

                            

                            

                            

                                ICMP-Echo + TCP-SYN auf diese Ports. Bewusst OHNE 80/443, da Firewalls diese oft für nicht existierende Hosts beantworten (falsches „online").

                        

                        

                            
                        

                    

                


                

                
                

                    
🕵️ Kali über Tor (MCP)

                    

                        
Ein Kali-Container, der nur über Tor ins Netz geht und von den Agenten per MCP angesprochen wird. Keine Shell — nur erlaubte Recon-Tools gegen die Ziel-Allowlist, gefährliche/Massen-Muster geblockt, alles auditiert. Braucht zusätzlich das Compose-Profil: docker compose --profile kali up -d. Nur eigene/autorisierte Ziele scannen.

                        

                            

                            

                            

                            

                            

                            

                                Kommagetrennt: CIDRs / IPs / Domain-Suffixe. Leer = nichts scannbar (fail-closed).
