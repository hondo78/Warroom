Entra ID — Login-Blocking (Conditional Access)

Schiebt geblockte IPs in eine Entra Named Location, die an eine Conditional-Access-Policy gebunden ist — M365-Logins von diesen IPs werden dann direkt bei Microsoft abgewiesen. Nutzt dieselbe App-Registrierung wie der M365-Collector, benötigt aber zusätzlich die Graph-Berechtigungen Policy.ReadWrite.ConditionalAccess + Policy.Read.All (Application, Admin-Consent).
Sicherheit: Die Policy wird im Report-Only-Modus angelegt — Erzwingung musst du bewusst im Entra-Portal aktivieren.

Pflicht für die automatische Policy-Anlage — UPN(s) oder Objekt-ID(s), kommagetrennt. Diese Konten werden nie geblockt (Schutz gegen Selbst-Aussperrung).

🤖 KI-Agent (Alert-Analyse)

Der Agent zieht periodisch neue Alarme heran, ruft ein LLM (OpenAI-kompatibel — LMStudio, Ollama, vLLM, OpenAI) und schlägt eine Aktion vor. Empfehlungen landen als pending in der Dashboard-Liste, bis sie ein Mensch freigibt — sofern Auto-Execute aus ist.

0 = deterministisch/konsistent, höher = kreativer. Für Security-Entscheidungen niedrig halten (0–0.3).
Obergrenze der Antwortlänge. Reasoning-Modelle brauchen Reserve für ihren internen „Think"-Block — großzügig lassen (≈3000).
⚠ Wenn aktiv, führt der Agent Block-IP und Acknowledge bei jeder Konfidenz ohne Freigabe aus. Isolate bleibt immer manuell.
Decisions mit Konfidenz ≥ dieser Schwelle laufen auch dann automatisch, wenn der Master-Switch aus ist. Default 90% — typische Auslöser sind dann: IPS High-Severity (0.92), Threshold-Hits (0.95), Subnet-Brute-Force (0.92). OSINT-only (0.85) bleibt unter der Schwelle und braucht Human-Approval. Auf 101 setzen → deaktiviert.
Wenn aktiv, prüft eine separate Schleife jede neue WAF-Zeile mit 4xx/5xx-Status pro Source-IP. Regel: ≥ Schwelle Fail-Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip. Decisions landen im Audit-Trail; whitelistete IPs werden ohnehin verworfen.
Anzahl an 4xx/5xx-Hits derselben IP in 24 h, ab der geblockt wird (Default 4).
Prüft jeden neuen IDP/IPS-Event pro Source-IP. Regel: Schwere = high/critical ⇒ sofort block_ip; sonst ≥ Schwelle Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip.
Erkennt Brute-Force-Versuche. Regel: ≥ Schwelle Failed-Logins in 24 h pro IP ODER schlechte OSINT-Reputation ⇒ block_ip.
Wenn ein /24-Netz in Summe ≥ N Failed-Login-Versuche in 24 h sendet UND die Versuche von ≥ M unterschiedlichen IPs kommen, werden alle aktiven IPs dieses Subnetzes geblockt. Verteidigung gegen koordinierte Botnets.
Welche Login-Versuche der Agent sieht (Default 60 Minuten).
Richtwerte, ab wann ein /24 als koordiniert gilt — werden dem Agenten als Hinweis übergeben; er darf bei klarem Muster begründet abweichen.
