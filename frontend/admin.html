Sophos Central API

OAuth2-Credentials aus dem Sophos Central API Token Management. Tenant-ID wird nach Login automatisch erkannt, falls leer.

Microsoft 365 Audit-Log

Entra-ID-App-Registrierung mit Admin-Consent. Der Collector holt Login-Ereignisse (UserLoggedIn / UserLoginFailed); Fehlversuche landen zusätzlich als Alerts auf der Attack-Map. Anzeige unter Microsoft 365.
Benötigte Application-Berechtigungen:
• ActivityFeed.Read (Office 365 Management APIs) — Login-Audit-Log.
• User.RevokeSessions.All (Microsoft Graph) — für die Login-Überwachung: Session-Widerruf bei Anmeldung von neuem Gerät/Standort.

Interne Hostnamen

Löst Hostnamen für interne (private) IPs auf und zeigt sie überall an, wo eine interne IP erscheint. Quellen in dieser Reihenfolge: Sophos-Endpoints → Reverse-DNS (PTR) → NetBIOS. Für PTR privater Bereiche trage die IP deines internen DNS-Servers ein (der Standard-Resolver des Containers kann das i.d.R. nicht).

Kommagetrennt. Leer ⇒ System-Resolver. PTR-Records müssen existieren.
Firewall DHCP (SFOS XML-API)

Liest DHCP-Zuordnungen (IP → Client-Name) von der Sophos-Firewall und ergänzt sie als Hostname-Quelle „dhcp". Der API-Benutzer muss in der Firewall API-berechtigt und dessen Zugriff für Warrooms IP freigegeben sein.

Aus: Firewall-Infos kommen aus der XML-API. An: legt zusätzlich pro Central-Firewall einen Karten-Pin an (kann Dubletten erzeugen).
XML-API-Entity (kommagetrennt möglich). Firmware-abhängig; Standard liefert reservierte Zuordnungen.

                        


                        

                            
                        

                    

                


                
                

                    

                        
Entra ID — Login-Blocking (Conditional Access)

                        

                            
                            
                        

                    

                    

                        

                            Schiebt geblockte IPs in eine Entra Named Location, die an eine
                            Conditional-Access-Policy gebunden ist — M365-Logins von diesen IPs werden
                            dann direkt bei Microsoft abgewiesen. Nutzt dieselbe App-Registrierung wie
                            der M365-Collector, benötigt aber zusätzlich die Graph-Berechtigungen
                            Policy.ReadWrite.ConditionalAccess + Policy.Read.All
                            (Application, Admin-Consent).
                            
Sicherheit: Die Policy wird im Report-Only-Modus
                            angelegt — Erzwingung musst du bewusst im Entra-Portal aktivieren.
                        

                        

                            

                            

                            

                            

                            

                            

                                
                                Pflicht für die automatische Policy-Anlage — UPN(s) oder Objekt-ID(s), kommagetrennt. Diese Konten werden nie geblockt (Schutz gegen Selbst-Aussperrung).

IOC-Auslieferung an die Firewall

                        

                            
                            
                        

                    

                    

                        

                            Zwei voneinander unabhängige Wege, die Blocklisten an die Firewall zu bringen — beide können gleichzeitig aktiv sein.
                            Pflege der Listen siehe Blocklist-Seite.
                        


                        

                            

                            

                                

                                    
                                

                                
                                    Die Firewall holt die Blocklisten als TXT-Feeds (ein Eintrag pro Zeile) selbst ab — als Third-Party-Threat-Feed konfiguriert, mit X-API-Key-Header.
                                    Aus ⇒ die Feeds liefern einen leeren Body (eine pollende Firewall leert damit ihre Liste).
                                
                                

                                    
IP-Feed: /ioc_IP

                                    
Domain-Feed: /ioc_domain

                                    
URL-Feed: /ioc_url

                                

                            


                            

                            

                                

                                    
                                

                                
                                    Warroom pusht die Blocklisten aktiv über die Sophos-Central-Firewall-API in den MDR-Threat-Feed der Firewall
                                    (POST /firewall/v1/firewalls/{id}/mdr-threat-feed/indicators). Nutzt die oben konfigurierten Sophos-Central-Zugangsdaten.
                                
                            


                            

                            

                                
                                Leer lassen, um an alle von Sophos Central gemeldeten Firewalls zu pushen.

🤖 KI-Agent (Alert-Analyse)

                        

                            
                            
                            
                        

                    

                    

                        

                            Der Agent zieht periodisch neue Alarme heran, ruft ein LLM (OpenAI-kompatibel — LMStudio, Ollama, vLLM, OpenAI) und schlägt eine Aktion vor.
                            Empfehlungen landen als pending in der Dashboard-Liste, bis sie ein Mensch freigibt — sofern Auto-Execute aus ist.
                        

                        

                            

                            

                                

                                    
                                

                            


                            

                            

                                
                            


                            

                            


                            

                            


                            

                            

                                

                                    
                                    
                                

                            


                            

                            


                            

                            

                                
                                0 = deterministisch/konsistent, höher = kreativer. Für Security-Entscheidungen niedrig halten (0–0.3).
                            


                            

                            

                                
                                Obergrenze der Antwortlänge. Reasoning-Modelle brauchen Reserve für ihren internen „Think"-Block — großzügig lassen (≈3000).
                            


                            

                            

                                
                                Sprache der LLM-Default-Prompts, der Analyst-Chat-Antworten und der Telegram-Meldungen. Eigene (überschriebene) Prompts bleiben unberührt.
                            


                            

                            

                                

                                    
                                

                                Wenn aktiv, führt der Agent nur nicht-destruktive Aktionen (acknowledge) ohne Freigabe aus. Block-Aktionen und Isolate bleiben immer manuell. Die Aktion ergibt sich allein aus den Schwellenwerten pro Quelle — es gibt keine Konfidenz-Berechnung mehr.
                            


                            

                            

                                

                                    
                                

                                
                                    Wertet den Sophos-Central-Event-Stream (getrennt von Alerts) aus — Endpoint-Threat/C2/Exploit-Events.
                                    Pro neuem Event der konfigurierten Typen entscheidet das LLM block_ip / isolate / acknowledge.
                                
                            


                            

                            

                                
                                Nur Events dieser event_type-Werte gehen ans LLM. Firewall-ATP-Events bewusst ausgenommen (über WAF/IPS abgedeckt).
                            


                            

                            

                                
                            


                            

                            

                                

                                    
                                

                                
                                    Wenn aktiv, prüft eine separate Schleife jede neue WAF-Zeile mit 4xx/5xx-Status pro Source-IP.
                                    Regel: ≥ Schwelle Fail-Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip.
                                    Decisions landen im Audit-Trail; whitelistete IPs werden ohnehin verworfen.
                                
                            


                            

                            

                                
                                Anzahl an 4xx/5xx-Hits derselben IP in 24 h, ab der geblockt wird (Default 4).
                            


                            

                            

                                
                            


                            

                            

                                

                                    
                                

                                
                                    Prüft jeden neuen IDP/IPS-Event pro Source-IP. Regel: Schwere = high/critical ⇒ sofort block_ip;
                                    sonst ≥ Schwelle Hits in 24 h ODER schlechte OSINT-Reputation ⇒ block_ip.
                                
                            


                            

                            

                                
                            


                            

                            

                                
                            


                            

                            

                                

                                    
                                

                                
                                    Erkennt Brute-Force-Versuche. Regel: ≥ Schwelle Failed-Logins in 24 h pro IP
                                    ODER schlechte OSINT-Reputation ⇒ block_ip.
                                
                            


                            

                            

                                
                            


                            

                            

                                
                            


                            

                            

                                
                                
                                    Wenn ein /24-Netz in Summe ≥ N Failed-Login-Versuche in 24 h sendet UND
                                    die Versuche von ≥ M unterschiedlichen IPs kommen, werden alle aktiven IPs
                                    dieses Subnetzes geblockt. Verteidigung gegen koordinierte Botnets.
                                
                            


                            

                            

                                
                            


                            

                            

                                

                                    
                                    
                                

                            


                            

                            

                                
                                Welche Login-Versuche der Agent sieht (Default 60 Minuten).
                            


                            

                            

                                
                            


                            

                            

                                
                                Richtwerte, ab wann ein Netz als koordiniert gilt — werden dem Agenten als Hinweis übergeben; er darf bei klarem Muster begründet abweichen.

🧹 Firewall-Log-Retention

                    

                        
Die Tabelle firewall_logs wächst schnell — die hochvolumigen Firewall-Verbindungslogs werden früher gelöscht als sicherheitsrelevante Typen (WAF/IPS/Auth/ATP). Löschung läuft batchweise im Hintergrund (alle 6 h) ohne Schreib-Locks.

                        

                            

                            

                                

                                    
                                

                            


                            

                            

                                
                                Gilt für log_type='Firewall' (Verbindungstracking — i. d. R. ~94 % des Volumens). NetFlow deckt Traffic-Analyse separat ab.
                            


                            

                            

                                
                                Gilt für alle übrigen Typen (WAF, IPS/IDP, Authentication, ATP, …).
                            

                        

                        

                            
                            
                        

                    

                


                
                

                    
🔌 MCP-Server — Log-Suche fürs LLM

                    

                        
Stellt eine read-only Suche über die Firewall-Syslogs als MCP-Server bereit (Streamable HTTP unter /mcp), damit ein MCP-Client (Claude Desktop/Code …) die Logs per LLM durchsuchen kann. Tools: search_logs, count_logs, aggregate_logs, describe_logs.

                        

                            

                            

                                

                                    
                                

                            

                            

                            

                                
                                Erforderlich, wenn aktiv. Im MCP-Client als Authorization: Bearer <Token> hinterlegen. Unabhängig vom Warroom-API-Key rotierbar.
